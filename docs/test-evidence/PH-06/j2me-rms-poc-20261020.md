# J2ME RecordStore PoC (time-boxed) — 2026-10-20

Prior: `j2me-blocker-resolution-spike-20261020.md` (RMS absent in J2ME-For-Web).

## Goal

Prove a **minimal standards-shaped** `RecordStore` can be implemented in isolation with automated tests — without integrating a J2ME VM into production.

## Deliverable

- `spikes/j2me-rms/record-store.mjs` — open/create/delete, add/set/get/delete/enumerate, MIDlet namespace isolation, quota `FULL`, injectable persistence.
- `spikes/j2me-rms/record-store.test.mjs` — Node test runner.

## Command / result

```bash
node --test spikes/j2me-rms/record-store.test.mjs
```

```text
✔ open/create/delete and namespace isolation
✔ insert update enumerate remove with integrity
✔ quota FULL and durable restart via persistence
✔ cannot delete while open
ℹ pass 4
```

Process-map clear + persistence reload simulates browser restart durability at the API layer.

## Explicitly out of scope (still BLOCKED for J2ME)

- Wiring into J2ME-For-Web / production frame adapter
- Browser IndexedDB/OPFS backend under COOP/COEP (API ready; not browser-proven)
- JAR/JAD validation, LCDUI, keypad, legal MIDlet offline gameplay
- GPL-2.0 distribution packaging of a full VM

## Decision

RMS **API PoC green**; J2ME platform remains **BLOCKED** until a legal MIDlet plays offline with this (or equivalent) store behind isolation.
